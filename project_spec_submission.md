# Scientific Research Knowledge Assistant — Project Specification

**Version 6.1 (submission edition)** | **Research goal:** Evaluate whether verified graph relationships improve source-grounded answers beyond vector, hybrid, and curated-fact search. The result may favor any approach. Implementation requirements are maintained in `project_spec.md`.

## 1. Project Overview & Context

**Problem:** Research methods, benchmark results, and limitations are scattered across scientific PDFs; conventional search can miss connections or conflate results from different studies. **Solution:** A Python research assistant that extracts source-attributed scientific claims, validates them through human review, stores papers and relationships in Neo4j, and answers questions using actual graph traversal. **Users:** Students, AI engineers, and researchers discover related studies, compare methods and experimental conditions, inspect source citations, and export evidence. The system verifies *what a publication reports*, not whether its scientific claims are independently true. Product usefulness and research performance are separate success criteria.

Initially resolve dependencies with `uv lock`, then use locked installs/runs. One chosen provider enables early live development; the secondary provider must pass text/structured-output tests before MVP integration acceptance. ## 3. Core Features & MVP (Minimum Viable Product)

1. **Curate and ingest:** Validate the pipeline on **five interconnected papers**, then extend to **20–30** using recorded selection criteria, not observed graph gains or held-out questions. Record identifiers, rights, URLs, hashes, citation metadata and source coverage. Check PDF extraction quality; create extraction passages and stable, tokenizer-safe retrieval chunks. Disclose the pilot's inclusion in the final corpus.
2. **Extract and verify:** Extract targeted `Method`, `Dataset`, paper-specific `Evaluation`, and `Finding` candidates with exact quotations. Initially cap each paper at eight extraction passages, 12 scientific claims and a 20-minute human-review timebox; log pending work and scope changes. Export source-linked CSV/JSONL review bundles; validation never grants approval. Pause claim-dependent work for human decisions while independent work continues. Only approved current revisions support authoritative facts. Track costs and review counts/time; preserve contradictions. Numerical comparisons require compatible dataset/version, split, metric and protocol, or an explicit caveat.
3. **Implement four retrieval conditions:** **Vector** searches chunks semantically; **Hybrid** combines vector and keyword chunk search with reciprocal-rank fusion (RRF); **Hybrid + Approved Facts** also searches the same approved facts rendered as indexed text, but does not traverse neighbors; **Graph** starts with the identical hybrid-plus-facts pool and adds evidence by traversing reviewed Neo4j relationships. These distinguish basic retrieval, curated knowledge, and graph connections without claiming perfect causal isolation.
4. **Enforce one evidence contract:** Every mode delivers at most **six** source-backed `EvidenceItem` units under **1,800 estimated context tokens**, counting quotations, metadata, claims, and graph paths. One fact and up to three supporting excerpts form one unit; duplicate facts/passages do not count twice. The tokenizer/estimator is fixed across modes. Measure evidence recall from what is actually supplied to generation.
5. **Make traversal executable:** Use four fixed Cypher templates: **shared datasets**, **shared methods**, **citations**, and **method/evaluation findings**. Use question aliases per entity kind, falling back to reviewed aliases shown in seed evidence for a missing kind. From at most four seeds, return five ordered rows per template; deduplicate/rank at most 80 intermediates to 40 graph candidates. Indexed starts, fixed paths, timeouts and query-plan checks also control database work. Rank by question-entity overlap, semantic similarity, path length, baseline rank and ID. Graph claims must be approved/source-linked; fallback returns baseline evidence unchanged and exposes requested/effective mode and reason. Freeze core selection contracts before claim-review development.
6. **Deliver practical workflows:** Streamlit supports discovery, correctly attributed comparison, approved limitations and evidence CSV export, each with development acceptance cases. Recheck current approvals on display/export; distinguish retrieval-only output from abstention. Preserve raw replies/failures and log citation-only abstention normalization. A **synthetic integration fixture** proves new cross-paper traversal beyond baseline candidates. Real papers test correctness, provenance and fallback without requiring a graph advantage. Reduce unsupported numerical comparisons rather than inventing values.
7. **Evaluate rigorously:** Use **24 questions** (six per category), with **8 development / 16 held-out**. Independent gold annotations map facts to alternative sets of source spans: every span in one support set must appear in actual generation context. Raw chunks and approved facts receive equal credit; graph claim IDs alone are insufficient. Score best-set evidence Recall@6 (unanswerable N/A), correctness `0/0.5/1`, citation support and abstention; distinguish corpus absence from retrieval failure. Randomize scoring IDs before mode reveal; report paired outcomes, latency, caching and preparation cost. Keep held-out data outside development context. Require a verified, hashed freeze and explicit final-run authorization; preserve original scores and disclose any later annotation amendments/reruns.
8. **Deep learning analysis:** Run the four retrieval conditions with one fixed MiniLM encoder and generator. Separately compare MiniLM with MPNet using **vector retrieval only** and the same chunks/questions/gold facts, each with its own index. This evaluates pretrained transformer embeddings, not training; fine-tuning is optional unless the professor requires it.

**Phase 2:** Improved table parsing, larger corpus, richer graph views, potential fine-tuning. **Out of scope:** Unverified automatic facts, autonomous agents, user accounts, production deployment, full systematic review, and guaranteed Graph RAG superiority.

## 4. Data Architecture & State Management

**Nodes:** `Paper`, `Chunk`, `Method`, `Dataset`, paper-owned `Evaluation` (metric, value, dataset version, split, protocol), qualitative `Finding`, and approved `FactText` (claim revision, searchable statement, supporting passages). **Edges:** `Paper–HAS_CHUNK→Chunk`, `Paper–CITES→Paper`, `Paper–REPORTS_EVALUATION→Evaluation`, `Evaluation–OF_METHOD/ON_DATASET/SUPPORTED_BY→Method/Dataset/Chunk`, `Paper–REPORTS_FINDING→Finding`, `Finding–ABOUT_METHOD/ABOUT_EVALUATION/SUPPORTED_BY→Method/Evaluation/Chunk`. Bibliographic citation edges do not themselves prove scientific findings. Source claims may span multiple chunks/pages.

**Common evidence item:** `{id, kind, paper_ids, source_chunk_ids, excerpts, approved_claim_ids, claim_revision, claim_text, conditions, graph_paths, origin, similarity, rank}`. Excerpts carry source hash and normalized-text offsets. Independent gold JSONL stores fact statements and alternative jointly required source spans, never retrieval hints. `FactText` has vector/full-text indexes and source lookup by ID; maintain separate 384-D/768-D chunk indexes and idempotent imports.

**Integrity and reproducibility:** Approval binds claim/source/entity revisions; changes invalidate graph/fact-text eligibility until human re-review. Export deterministic graph/schema/review manifests and verify reconstruction into a fresh disposable test volume before freezing. Optional native dump/load requires an offline database and a planned outage; never overwrite working data. Preserve actual contexts/prompts/outputs and retrieved ranks because fresh model calls or approximate indexes may differ. Keep audit/configuration hashes and warm/cold/cache records; missing conditions remain unknown.

## 5. AI System Rules & Aesthetics (The "Vibe")

**Code:** Read this spec first; write typed, modular Python with docstrings, Pydantic validation, fixed parameterized Cypher, and committed dependency locks. No invented sources, test scores, or claims. **Errors/security:** Treat documents as untrusted input; verify quoted evidence; never auto-approve or silently change LLM provider. Surface failures, use bounded retries, redact secrets. **Tests:** Cover wrong-paper result contamination, aliases, approval invalidation, fact-text synchronization, evidence budgets, actual traversal and fallback, ablation parity, alternative gold sets, abstention, embedding dimensions, and reproducible run logs. **UI:** Minimal, accessible and dark-friendly; clearly distinguish quotes, approved claims, graph connections, LLM synthesis, limitations, and downloadable source evidence.
