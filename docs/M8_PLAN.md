**Status: M8.1-M8.3 complete; M8.4-M8.5 not_started.** The separate `codex/m8-user-collections` product now supports named collections, bounded uploads/links, Vector/Hybrid QA with optional local Qwen, exact source cards/PDF access and checked exports. [M8.3 checks and launcher](M8_3_REPORT.md), [import outcomes](M8_2_REPORT.md), [foundation](M8_1_REPORT.md). The class progress document remains a preimplementation snapshot. Two bounded live generation checks establish product operation, not quality improvement; no claims/approvals, paid/private operations or new study occurred.

## User experience and first release

A user creates a named collection, uploads 1-10 text-based research PDFs or supplies supported links, watches processing status, and asks questions with exact source passages and page citations. Initial links support arXiv abstract/PDF URLs and direct public PDF URLs. Login-only pages, paywall access, unattended crawling, arbitrary HTML, scanned-document OCR and non-PDF formats remain outside the first release.

Vector and Hybrid become available after indexing. Hybrid + Approved Facts and Graph require that collection's own reviewed claims and current review projection. Extraction proposals are never automatically approved. A user can finish ordinary passage-based QA before deciding whether to review graph proposals. The existing pretrained local Qwen/embedding stack is reused without training; new-topic quality is not guaranteed.

## Boundaries and shared contracts

- Keep the two original curated collections as preserved examples; do not add user documents to their corpus IDs, source projections or review journals. Before writes, create an explicit isolated writable user-collection target/namespace and local storage/review root. Do not repoint any baseline, retained M5 or consumed evaluator scope. Resource preflight must account for existing services.
- Implemented `UserCollection` stores stable UUID, immutable revision/previous hash, name, timestamp, document versions and optional index binding. Corpus IDs include the collection/revision; review paths are derived from the same binding. `ImportJob` stores exact inputs/collection head, hash-chained status and result/reason. Metadata never grants runtime readiness or approval. `CollectionRegistry.describe` remains metadata-only; `collections.workspace` separately verifies actual live readiness for QA/display/export. Contracts and fixed v1 limits are in `collections/contracts.py`.
- App services calculate source hashes and manifests from the inputs. Preserve URL or uploaded filename, PDF page coverage, source offsets and exact quotations. Unknown bibliographic metadata stays unknown; an unavailable OpenAlex match does not prevent passage-only QA. Repeated content is deduplicated within a collection, and later versions receive new immutable identities.
- `collections/` owns registry, jobs and collection/review bindings; `ingestion/` owns input resolution, PDF processing and indexing; `review/` owns proposal/decision eligibility. Existing retrieval/pipeline/generation/product/export services remain shared. CLI and Streamlit only call those services; no UI-owned Cypher, hidden cross-collection fallback or mode-specific validation copies.
- Reuse the six-unit/1,800-estimated-token evidence contract, source/citation checks, current-review-head guard, requested/effective mode and fallback visibility. Standard local generation retains 4096/512 bounds and explicit opt-in. New engineering probes require their own numerical scope/accounting before execution; used readiness/study allowances are not reused. No new paid allowance is granted by this plan.

## Fixed first-release policy (M8.1)

- At most 20 named collections, 100 immutable revisions per collection and 10 unique PDFs per revision. Each PDF: 25 MiB and 100 pages maximum. Each collection: 100 MiB, 300 PDF pages and 3,000 indexed chunks maximum. M8.2 enforces actual streamed bytes, PDF pages, unique membership and pre-embedding chunk totals. Duplicates are resolved before counting new members, so an already-full collection can still recognize a duplicate. The separate parser policy bounds each PDF subprocess to 60 seconds and extracted text to 100,000 characters/page and 2,000,000/PDF. Blank/image-only pages are explicitly omitted with coverage recorded; fully unreadable/scanned, encrypted and invalid PDFs fail without OCR.
- One active foreground import across the workspace; at most 10 input references per job. Reserve before work; keep interrupted/failed histories and never auto-take over a stale lock or retry. Metadata-only queueing does not send requests.
- HTTPS only, default port, no credentials/fragments/IP literals; direct PDF paths or modern `YYMM.NNNN[N][vN]` arXiv abstract/PDF identifiers. URL syntax limit 2,048 characters. Download policy: 30-second request timeout, at most three redirects, zero automatic retries; M8.2 checks all DNS answers and each redirect as public/global, rejects transitional/local addresses, pins the socket IP while verifying the original TLS hostname, ignores proxy credentials and caps streamed bytes. A single absolute deadline and socket watchdog cover DNS/TCP/TLS/headers/body, including continuously dribbling responses. Syntax validation alone never grants network access.
- Root is checkout-local `data/user-collections/`, with owner digest and collection/revision-derived review directories. Fixed record/envelope hashes, create-only history, optimistic heads and an owned exclusive lock detect corruption/staleness; this is local single-user procedural isolation, not an adversarial security sandbox.
- Target is a new `dbu-m8-user-<UUID>` container with its own `/data` and `/logs` volumes and nondefault loopback Bolt port. Exact image/container/project/ports/volumes, writable database access, workspace owner and absence of frozen corpora are checked before shared graph writes. Mixed M5/M8 declarations are rejected. No old projection/index/volume is restored or repointed.

## M8.2 source and publication contract

Raw sources and per-paper inspection/chunk/vector caches live under the owned user-collection root. Derived aggregate snapshots remain in this checkout's `data/processed/<collection-corpus-id>/` so the existing loader/retrieval services can read them unchanged. Aggregate IDs bind scope, collection, revision and document membership. Input URLs/filenames remain in `DocumentVersion.source`; shared chunks use the content identifier `userpdf://<SHA-256>`, not a fabricated public web URL. M8.3 renders the original reference and a checked local PDF download alongside page citations. This keeps the same PDF's source/chunk metadata identical across collections while preserving each collection's original input and separate corpus/review binding.

Each queued batch acquires an owned worker lock. All sources/pages/chunks pass preflight before embeddings/index publication. States advance once through resolving/parsing/indexing to ready, duplicate, failed or interrupted. A successful new collection revision requires an exact final import commit receipt as well as ready job history; interrupted multi-file publication cannot be silently treated as ready or auto-resumed. Failed/partial source/cache/index artifacts are retained, and existing revisions are never overwritten. Metadata descriptions expose no product modes; the separate M8.3 workspace service validates live readiness. No paper claims are extracted or approved by import.

## Scope differences from the finished class project

It does not replace the original results, remove human-review rules, enable unattended approval or add cloud accounts/authentication. Graph schema/prompt changes for a new subject require explicit versioning rather than silently reinterpreting older reviewed entities.

## M8.3 QA and display contract

`collections.workspace` verifies committed publication, the exact collection head/scope, snapshot and member paths, source PDF/chunk hashes and live indexes. UI and CLI call the same query/export boundary; only explicit submits retrieve or generate. Saved answers bind collection/revision/source/target and revalidate before display/download. Imports, questions and revision edits share mutual-exclusion guards; stale locks remain errors. The new UI offers baseline/reference Vector/Hybrid only, optional explicit generation, readable source labels, original references and checked local PDFs. The launcher starts only the retained attested container ID. No automatic Graph eligibility, extraction/approval, provider substitution, retry or hidden cross-collection fallback.
