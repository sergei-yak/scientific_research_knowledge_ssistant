## M1 design bindings (before M2; implemented through M3.1)

- **Vector:** corpus-specific ANN pool of 24; recompute actual cosine, stable-ID ties, retain 12 candidates. Initial development threshold is 0.30. Common assembly selects at most six units/1,800 estimated tokens. Actual candidates, scores, omissions and context are saved; this is approximate retrieval, not exact global nearest-neighbor search.
- **Fusion:** Hybrid uses chunk-vector and chunk-full-text top-12 lists. Hybrid + Facts uses those plus fact-vector/fact-full-text top-12 lists, each with equal contribution to RRF `k=60`; deduplicate IDs within lists and break fused ties by stable ID. Graph reuses that exact pool. `retrieval/ranking.py` supplies the rank-only contract; the three extra modes were implemented in M3.1.
- **Embedding text:** raw chunks use exact normalized text; fact text deterministically includes reporting paper, canonical method/dataset, assertion and sorted conditions. Quote bundles are attached separately. Reject overlong fact embedding text for revision, rather than silently truncating conditions. Query/graph-only cosine always uses the same MiniLM revision and canonical embedding input.
- **Assembly:** raw overlap is removed by source page/offset while retaining exact chunk-local mappings; keep facts atomic and deduplicate claim revisions. Render exact shared source spans once via source references, preserving distinct claims. Count every displayed source/claim/path/metadata field; reject an oversized unit instead of hiding text. The scorer checks the actual reconstructed context, source hashes, AND/OR support and alternative sufficient fact sets, never graph claim IDs.
- **Graph selection:** reviewed aliases use NFKC/casefold and word boundaries; count distinct canonical question entities, not occurrences or seed-only aliases. Ambiguous aliases are not auto-resolved. Alias fallback is per kind (D29). At most four assembled baseline seeds; fixed routes below, one cross-paper transition per route. Each query starts at indexed paper/claim IDs, filters current approval/owner/corpus eligibility early, orders by reporting-paper/claim/chunk IDs and limits to five rows. At most 80 returned intermediate rows become 40 unique candidates using the spec's alias/cosine/path/baseline/ID order; duplicate targets retain their shortest, then lexically stable path. A configurable read-transaction deadline and inspected EXPLAIN/PROFILE plans also bound/measure work; LIMIT 5 does not bound operator rows. No unrestricted paths or generated Cypher.

| Implemented template | Explicit relationship route from a seed, then source eligibility checks |
|---|---|
| Shared dataset | `Chunk <-HAS_CHUNK- Paper ->REPORTS_EVALUATION Evaluation ->ON_DATASET Dataset <-ON_DATASET Evaluation ->SUPPORTED_BY Chunk` (five edges). |
| Shared method | Same five-edge route with `OF_METHOD` and `Method`. Both evaluations retain their own reporting papers. |
| Citation | `Chunk <-HAS_CHUNK- Paper ->CITES Paper ->REPORTS_EVALUATION/REPORTS_FINDING Claim ->SUPPORTED_BY Chunk` (four edges); incoming citation is a separate fixed branch, sharing the five-row total. |
| Finding | Seed paper's evaluation to a shared method, then incoming `ABOUT_METHOD` from a finding and `SUPPORTED_BY` to its chunk (five edges); `ABOUT_EVALUATION` is a fixed shorter branch. |

Every target is joined to its actual reporting paper in the same selected corpus and checked for current approval/revision/support, including finding targets. Metadata citations alone never authorize claims. Graph fallback returns the original Hybrid + Facts assembly unchanged if no new eligible item survives. M3.1 evidence is in `docs/M3_1_REPORT.md`; these conditions do not identify a pure causal effect of traversal independent of reranking.

## Shared contracts and artifacts

Implement and validate these before their first consumers; use the domain fields in spec section 4 rather than maintaining a second schema here.

- **Source identity:** `PaperManifestEntry`, `Chunk`, `SourceExcerpt` and `SourceSpanRef` use spec section 4's immutable normalized text and offset/hash convention. Validate multi-page support and pass only actually rendered spans to scoring.
- **Claims/review:** `ClaimRevision` covers Evaluation/Finding payloads and supporting excerpts. `ReviewDecision` binds reviewer, decision, reason, timestamp and source/entity revisions. Only current human-approved revisions produce `FactText` or authoritative graph candidates.
- **Providers:** `LLMClient` returns validated text/structured results plus usage/model metadata, or an explicit error. Capture full request identity for caches; errors and unavailable usage are not successful zero-cost responses.
- **Retrieval:** `QueryRequest` carries question, requested mode and snapshot identity. `RetrievalResult` contains assembled `EvidenceItem[]`, estimated token count, requested/effective mode, fallback reason, and candidate/path audit records. Apply the spec's six-unit/excerpt/token limits after rendering.
- **Answer/run:** `AnswerResult` references returned excerpt IDs and distinguishes insufficient evidence. `RunArtifact` joins configuration/snapshot hashes, retrieval result, rendered-context hash, provider output and timings. `workflow` and `generation_requested` identify the operation; `result=null` means no accepted answer, never automatic abstention. Generation failures carry the actual retrieval and any available raw reply in `QueryExecutionError.artifact`. Historical answer artifacts retain default workflow `ask`. Citation existence is machine-checkable; semantic support still requires evaluation.
- **Evaluation:** `EvaluationQuestion` and a graph-independent gold JSONL implement section 4's annotation contract. Unit-test alternative fact sets, alternative passage sets, jointly required spans, truncation and graph-ID independence before M2. Store blinded `HumanScore` separately from the reveal mapping. Gold annotations are evaluator inputs, never retrieval inputs.

Keep public configuration, synthetic fixtures and sanitized manifests under version control. Use ignored local `data/` and `runs/` for source/review/run artifacts. Development annotations may live there; held-out questions/gold/reveal mapping live in an evaluator-controlled **external** directory, not a repository file hidden only by `.gitignore`. Define JSONL/CSV columns and round-trip tests when introduced. CLI operations cover manifest validation, ingest, review export/import, index build, query, snapshot export/restore and evaluate; record executable flags when available.

## Recovery and freeze procedure (implement by M3)

1. Quiesce application writes; export a consistent snapshot into a new directory: stable-ID-sorted nodes/relationships including embeddings, schema/index definitions, review log, source/chunk manifests, code/config/prompt identities and checksums. Keep source documents or verified local copies available for reconstruction.
2. Verify export hashes; restore through the graph repository into a **fresh disposable Neo4j volume** with the pinned image. Recreate indexes and await `ONLINE`; never import over the working volume.
3. Compare semantic export checksums, IDs/counts, approval eligibility, support links and vector dimensions. Run development queries/acceptance scenarios, revocation fixtures and offline scoring replay. A rebuilt approximate index need not reproduce identical top-k ranks; preserve original run candidates/contexts.
4. Record exact export/restore commands, image, volume targets and outcomes in the milestone evidence. This tested logical route is required; an untested backup file is insufficient.
5. Optional native backup: schedule database downtime, stop the owning service, and use matching-version admin tools in a one-off container for `neo4j-admin database dump neo4j --to-path=/backups`. Load with `neo4j-admin database load neo4j --from-path=/backups` into a fresh offline target. Record actual Compose mounts/flags before use, restart the service and check health. Do not copy a running database's files or overwrite a working volume.
6. M4 freeze records hashes of corpus/graph/review exports, lockfile/code, prompts/configuration, annotation files and the restore verification record. Protect the frozen snapshot with an application write guard; do not assume Community Edition supplies Enterprise access-control features. The evaluator supplies private-file hashes without exposing content to the development agent.
