## M1 design bindings (before M2; implemented through M3.1)

**Baseline profile only.** The frozen bindings below remain the reproducibility reference. R2 requirements explicitly replace their seeding/route/ranking choices for the new profile; do not change these historical bindings or treat them as simultaneously active V2 algorithms.

- **Vector:** corpus-specific ANN pool of 24; recompute actual cosine, stable-ID ties, retain 12 candidates. Initial development threshold is 0.30. Common assembly selects at most six units/1,800 estimated tokens. Actual candidates, scores, omissions and context are saved; this is approximate retrieval, not exact global nearest-neighbor search.
- **Fusion:** Hybrid uses chunk-vector and chunk-full-text top-12 lists. Hybrid + Facts uses those plus fact-vector/fact-full-text top-12 lists, each with equal contribution to RRF `k=60`; deduplicate IDs within lists and break fused ties by stable ID. Graph reuses that exact pool. `retrieval/ranking.py` supplies the rank-only contract; the three extra modes were implemented in M3.1.
- **Embedding text:** raw chunks use exact normalized text; fact text deterministically includes reporting paper, canonical method/dataset, assertion and sorted conditions. Quote bundles are attached separately. Reject overlong fact embedding text for revision, rather than silently truncating conditions. Query/graph-only cosine always uses the same MiniLM revision and canonical embedding input.
- **Assembly:** raw overlap is removed by source page/offset while retaining exact chunk-local mappings; keep facts atomic and deduplicate claim revisions. Render exact shared source spans once via source references, preserving distinct claims. Count every displayed source/claim/path/metadata field; reject an oversized unit instead of hiding text. The scorer checks the actual reconstructed context, source hashes, AND/OR support and alternative sufficient fact sets, never graph claim IDs.
- **Graph selection:** reviewed aliases use NFKC/casefold and word boundaries; count distinct canonical question entities, not occurrences or seed-only aliases. Ambiguous aliases are not auto-resolved. Alias fallback is per kind (D29). At most four assembled baseline seeds; fixed routes below, one cross-paper transition per route. Each query starts at indexed paper/claim IDs, filters current approval/owner/corpus eligibility early, orders by reporting-paper/claim/chunk IDs and limits to five rows. At most 80 returned intermediate rows become 40 unique candidates using the spec's alias/cosine/path/baseline/ID order; duplicate targets retain their shortest, then lexically stable path. A configurable read-transaction deadline and inspected EXPLAIN/PROFILE plans also bound/measure work; LIMIT 5 does not bound operator rows. No unrestricted paths or generated Cypher.

|---|---|
| Shared dataset | `Chunk <-HAS_CHUNK- Paper ->REPORTS_EVALUATION Evaluation ->ON_DATASET Dataset <-ON_DATASET Evaluation ->SUPPORTED_BY Chunk` (five edges). |
| Shared method | Same five-edge route with `OF_METHOD` and `Method`. Both evaluations retain their own reporting papers. |
| Citation | `Chunk <-HAS_CHUNK- Paper ->CITES Paper ->REPORTS_EVALUATION/REPORTS_FINDING Claim ->SUPPORTED_BY Chunk` (four edges); incoming citation is a separate fixed branch, sharing the five-row total. |
| Finding | Seed paper's evaluation to a shared method, then incoming `ABOUT_METHOD` from a finding and `SUPPORTED_BY` to its chunk (five edges); `ABOUT_EVALUATION` is a fixed shorter branch. |
